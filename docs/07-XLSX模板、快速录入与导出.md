## 7.8 XLSX 模板、快速录入与单据导出

### 7.8.1 模板版本与字段

入库、出库分别提供独立 `.xlsx` 模板，模板只包含“录入数据”和“填写说明”两个工作表。单据头字段集中在“录入数据”前 2 行的表头区，明细自第 4 行起以二维表填写；“填写说明”包含模板标识、`template_version`、字段必填性、数量规则和示例。首版模板版本分别为 `INBOUND_V1`、`OUTBOUND_V1`；表头区布局在 0.1.0 发布前确定，仍属于首版 `V1`，发布后不兼容变更必须递增版本并保留明确错误提示。解析时允许第三个工作表“单据信息”存在，以接收本系统导出的文件，但该表全部内容只作展示、不得参与业务解析；其他额外工作表均拒绝。

表头区固定如下，模板下载时 B1–B2 留空：

| 位置    | 内容                                | 入库 | 出库 |
| ------- | ----------------------------------- | ---- | ---- |
| A1 / B1 | 标签“仓库名称” / 仓库名称值         | 必填 | 必填 |
| A2 / B2 | 标签“管理部门名称” / 管理部门名称值 | 必填 | 必填 |

“录入数据”第 3 行为明细列标题，第 4 行起为明细数据：

| 入库列 | 出库列 | 字段         | 规则                                                   |
| -----: | -----: | ------------ | ------------------------------------------------------ |
|      1 |      1 | 项目名称     | 可空；逐行解析，不要求全文件一致；空表示该行不关联项目 |
|      2 |      2 | 一级分类名称 | 每行必填                                               |
|      3 |      3 | 二级分类名称 | 可空；为空表示物资直接属于一级分类                     |
|      4 |      4 | 物资名称     | 每行必填；与一、二级分类共同唯一定位物资               |
|      5 |      5 | 数量         | 每行必填，十进制正数，遵守物资数量类型与精度           |
|      6 |      — | 厂家名称     | 入库每行必填；出库模板不得存在此列                     |
|      7 |      6 | 备注         | 可空；逐行独立；去首尾空白后最多 500 字符              |

表头区标签、位置和明细列顺序固定；表头区标签不符或位置移动、明细列缺失/重复/顺序不符均为文件级错误。仓库和管理部门是单据级字段，一个文件只对应一个单据头；不得从明细行推导或覆盖表头区。备注不是单据头字段，按明细行保存、每行独立，不参与仓库/部门解析，也不影响同一物资同一项目的重复判断。表头区 B1–B2 只接受文本或空单元格，公式按文件级错误拒绝；工作簿中的外部链接同样整份拒绝。

模板所有业务资料字段均填写名称，不填写 UUID 或业务编码。模板下载由服务端动态生成，名称列不设置绕过服务端校验的可信选项；即使用户修改了显示格式，仍须按单元格文本重新校验。数量列预设为文本格式；普通数值单元格可接受，但服务端必须从工作表 XML 中该单元格的 `<v>` 原始数值词法读取十进制字符串，再转 `Decimal`，禁止使用 `openpyxl` 的 `cell.value` 浮点结果、进行浮点换算或隐式舍入。`.xlsx` 中数值单元格的原始词法由实现层读取；若读取不到原始词法，应按行级错误拒绝该行，不得退化为二进制浮点解析。

### 7.8.2 名称解析与重复处理

1. 名称仅去除首尾空白后精确匹配，不做模糊匹配、大小写折叠或内部空白删除。
2. 仓库与管理部门在表头区各解析一次：名称为空、未找到或已停用均为文件级错误，整份文件拒绝，不进入行级解析。项目、厂家在数据库内按名称查询；名称在各自表内唯一（见[《数据模型与实体约束》6.8](05-数据模型与实体约束.md#68-快速录入的名称索引)），查询至多命中一条，找不到即错误，不自动创建、不改名。项目按每行名称解析，匹配后必须启用；入库厂家每行必填且必须启用；同一文件各行的项目互不要求一致。
3. 一级分类与二级分类按给定父子关系解析。一级分类全局唯一；二级分类只需在所属一级分类内唯一，不同一级分类下的同名二级分类不得混淆。二级分类名称为空时，只匹配直接归属于该一级分类的物资；非空时必须同时匹配二级分类及其一级父分类。
4. 物资名称只在其直接所属分类内唯一，不同分类允许同名，因此“一级分类名称 + 二级分类名称 + 物资名称”即可唯一确定物资。分类只用于消歧，不改变物资 UUID、物资编码唯一性或库存维度；正常数据下按该组合命中至多一条，仅当异常或损坏数据导致多条命中时报 `MATERIAL_NAME_AMBIGUOUS`，不得任选一条。
5. 不自动创建或修改任何仓库、部门、项目、分类、物资或厂家。所有用于新入库表单的资料必须启用，保存和提交时仍须再次检查；出库分类和物资按库存及出库流程校验，不受停用限制。
6. 同一文件重复定位到相同 `material_id` 且项目相同（含均未填写项目）时，重复行按行级错误处理，不合并数量；备注内容不同不改变该判断。同一物资对应不同项目的行合法，可分别填入，不受此限。

### 7.8.3 文件级与行级错误

**文件级错误整份拒绝，不改变当前表单：**

- 文件无法读取、不是合法 XLSX、超过 5 MiB、非空数据行超过 2,000 行，或解压后尺寸/工作表结构异常。
- 模板标识或版本不受支持、解析类型与模板类型不符、工作表缺失或出现额外工作表、表头区标签或位置不符、明细列缺失/重复/顺序不符。
- 出库文件出现厂家列。
- 表头区仓库或管理部门为空、名称未找到或已停用，或表头区单元格为公式；工作簿含外部链接时整份拒绝。
- 全部数据行为空或全部行失败，即没有任何有效明细。

服务端不执行宏、外部链接或公式；明细行含公式时按行级错误处理，而非把公式计算结果当作输入。

**行级错误跳过，其余有效行填入页面：** 单行必填字段为空、项目或厂家名称未找到、项目/厂家/入库分类/入库物资停用、分类关系不符、数量格式/精度/范围错误、整数物资出现小数、入库厂家缺失、同一物资同一项目重复、备注超过 500 字符，以及明细行中的公式单元格。出库的分类和物资停用不作为行级错误，仍按库存及出库流程校验。空行不参与计数，隐藏行不跳过校验。

页面必须明确区分全部填入、部分填入和失败，展示总行数、成功填入/跳过行数及错误摘要。部分填入必须显著显示“部分明细未填入，请核对后再保存或提交”，不得只提示“解析成功”。错误摘要至少包含 Excel 原始行号、错误字段、错误代码和原因；不生成或下载 XLSX 错误报告。错误只在本次新建页保留，不随草稿持久化；页面刷新或离开后不要求恢复。

### 7.8.4 无副作用解析与填单流程

1. 仅在新建入库或出库页提供解析入口，已有草稿编辑页不提供。当前表单非空时，必须先提示“解析成功后将替换当前单据头和全部明细”，经用户确认再上传；不追加明细。
2. 客户端以 `multipart/form-data` 上传 `file` 并提供 `doc_type`；服务端校验 CU 权限、CSRF 和账户状态。解析接口不要求 `request_id`，不计算用于业务去重的文件哈希，不保存任何解析状态。
3. 在 5 MiB 限制内流式接收，使用 `openpyxl` 只读模式解析，不调用 Excel/LibreOffice，不执行宏、外部链接或公式；文本数量单元格直接读取字符串，普通数值单元格按 7.8.1 从工作表 XML 的 `<v>` 节点取得原始十进制词法后转 `Decimal`，禁止使用 `cell.value` 先转二进制浮点。
4. 在不持有数据库写锁的情况下完成解析和基础资料批量查询。解析接口不开启 `BEGIN IMMEDIATE`，不写单据、审计或任何解析记录；同一文件重复解析只重复返回结果。
5. 文件级失败返回错误且不改变原表单。解析成功后，前端才一次性替换当前单据头和全部有效明细，并显示跳过行摘要；解析结果中的单据头仅来自表头区 B1–B2，备注仅来自各行明细，不从明细行推导仓库或部门；有效行可继续手工编辑。
6. 解析结果不是草稿。用户点击“保存草稿”才调用普通 `POST /documents`；点击“提交生效”依次调用普通创建和提交接口。保存及提交必须重新校验全部 ID、资料状态、数量和库存，不信任解析响应。
7. 页面关闭、解析后未保存或用户放弃操作均不产生业务数据。草稿创建及提交的重试规则按[《库存计算与单据业务流程》7.2](06-库存计算与单据业务流程.md#72-通用草稿规则)执行，与文件是否重复解析无关。

### 7.8.5 单张单据导出

1. 每张入库单或出库单可独立导出 `.xlsx`，本期不提供多单清单导出。导出权限为 CU。
2. 工作簿包含“录入数据”“填写说明”“单据信息”。“录入数据”与对应模板使用同一表头区布局：B1 仓库名称、B2 管理部门名称，第 3 行为明细列标题，第 4 行起为明细；备注按明细行导出。“填写说明”与模板一致，并注明该文件由系统导出；“单据信息”单独列示正式单号、类型、状态、制单人、生效时间、涉及项目（去重列表）、软删除状态等系统字段，不混入录入数据。
3. 草稿按当前基础资料名称和分类导出，备注取当前明细行文本；已生效及已软删除单按历史快照导出，逐行项目名称和备注均取明细快照。
4. 导出文件可作为留档或快速录入参考；再次解析仍按当前资料匹配和校验，不保证历史文件可原样填入。
5. 导出的明细超过 2,000 行时仍允许下载，但页面和“填写说明”必须提示不能用于快速录入。导出的数量以文本单元格写入并保留三位小数；所有用户可控文本（含逐行备注）必须以字符串单元格写入，禁止以 `=`, `+`, `-`, `@` 开头被解释为公式。文件名包含安全单号和文档类型，响应使用安全的 ASCII 回退名及 RFC 5987 中文文件名编码。
