## 15. 实施顺序与完成定义

### 15.1 推荐实施顺序

1. 项目骨架、配置、日志、健康检查和测试夹具。
2. 单一数据库、统一账户、会话、API Key 哈希与生命周期、CSRF、初始公司管理员。
3. 用户与基础资料、六类统一 `code` 自动生成与计数器、两级分类与物资归属规则、分类删除与停用阻断条件、六类名称唯一约束、数量转换、审计。
4. 草稿（含逐行项目与拆行唯一性）、库存视图与余额上限、入库和出库事务。
5. 单据软删除（含事务内负库存/余额上限校验）、项目停用、主数据删除停用与启用规则（含分类自底向上停用、启用上级校验与名称查重）、并发与故障测试。
6. XLSX 模板、无副作用解析、新建页填单与错误摘要、手动保存/提交、单张导出及安全测试。
7. MCP Streamable HTTP 挂载、动态工具清单、六类查询与新增、实时库存查询、以 `code`/`doc_no` 定位及输出业务编码、关联引用参数到目标 `code` 的转换、原子直接提交、审计及协议/权限/故障测试。
8. 全部页面（含“我的 API Key”）、API 契约、权限与端到端测试。
9. Docker 镜像（`only-stock:0.1.0`）、Compose、备份恢复、首次建库 schema、性能和验收报告。

### 15.2 完成定义

第一阶段发布 0.1.0 版本镜像，只有同时满足以下条件才可发布：

- 第 13 章（[《验收标准》](16-验收标准.md)）核心功能、权限、精度和原子性条目全部通过。
- 操作员对全部管理接口及修改、删除他人出入库单的越权测试均被拒绝，且可修改、删除本人单据并提交全部普通出入库草稿。
- 并发负库存、软删除负库存、余额上限、重复提交和故障回滚测试通过。
- 密码重置与本人改密、规范化请求指纹、统一错误 `details` 结构、单据厂家筛选和最后管理员并发保护测试通过。
- 项目按明细可选、可混用、可按项目拆行；停用项目按行拒绝；摘要项目列表与按项目筛选口径测试全部通过。
- 六类基础资料均使用系统自动生成的 `code`，页面/API/MCP 无人工编码入口，并发唯一、不可修改、停用删除不复用及失败回滚测试全部通过。
- 分类删除与停用边界、六类基础资料停用后可启用及启用上级校验、分类/物资/仓库/部门/项目/厂家名称唯一性与规范化查重、并发查重及跨分类解析消歧测试全部通过。
- 入库/出库模板、名称缺失、部分填入、无副作用解析、普通数值 XML 精度、手动保存/提交和 XLSX 安全测试通过；确认不存在直接导入建单的数据表和接口。
- 备份恢复演练成功，恢复后的库存与单据核对一致；7 个成功备份集清理、[《Docker 部署与运维》10.7](13-Docker部署与运维.md#107-恢复要求)的恢复及回滚命令均按验收项通过。
- 10 万明细性能测试达到基线或形成经确认的调整结论。
- OpenAPI、数据库迁移、部署文档与实际镜像（`only-stock:0.1.0`）一致。
- `uv run ruff check .` 与 `uv run ruff format --check .` 全量通过，不存在未说明的 `# noqa` 或临时禁用规则，配置与 [《技术架构与代码组织》3.5](02-技术架构与代码组织.md#35-代码风格与-ruff-校验) 一致。
- 镜像无硬编码密码或 API Key，运行日志无敏感信息，初始密码已移除。
- 标准 MCP 客户端可通过 `/mcp` 初始化；CA/OP 工具清单分别为 13/8 个，直接越权调用被拒绝；Key 单次显示、哈希存储、吊销及账户变化联动测试全部通过。
- MCP 六类查询与新增、实时库存查询、`code`/`doc_no` 定位、输出不含内部 ID、业务编码关联、草稿/直接提交、原子回滚、300 秒窗口去重、MCP 审计、限流和 Host/Origin 安全测试全部通过。
