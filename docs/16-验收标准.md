## 13. 关键约束与验收标准

以下验收条目均可通过 API、数据库检查、页面操作或自动化测试验证。除性能条目外，任一核心条目失败均不应验收通过。

### 13.1 角色、账户与权限

| 编号         | 验收标准                                                                                                             | 验证方法                                                |
| ------------ | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| ACC-ROLE-001 | 空数据库首次启动可按环境变量创建一个公司管理员；重复启动不重复创建；首次登录强制改密                                 | 两次启动并查询用户数量，走首次登录流程                  |
| ACC-ROLE-002 | 公司管理员可创建和管理公司管理员与操作员；创建失败时不产生可登录的半成品账户                                         | 正常创建并注入写入故障                                  |
| ACC-ROLE-003 | 公司管理员可管理用户、仓库、部门、项目、分类、物资和厂家；六类主数据创建后不可修改                                   | 逐项执行新增、修改、删除、停用及查询                    |
| ACC-ROLE-004 | 操作员不能管理用户或任何基础资料，不能查询审计或执行备份；越权 API 返回 403                                          | 逐项调用管理 API，而非只检查按钮                        |
| ACC-ROLE-005 | 操作员仅可修改、删除本人创建的出入库单，不得修改、删除他人单据，但可提交全部普通出入库草稿；管理员可操作全部出入库单 | 两账户交叉修改、删除和提交普通草稿并核对权限            |
| ACC-ROLE-006 | 禁用用户后旧会话和全部 API Key 立即失效；最后一名公司管理员不能被禁用或降级；两名管理员并发互相禁用/降级时至少保留一名启用管理员 | 禁用后重放旧 Cookie 和 Bearer Key，并测试最后管理员保护及并发操作 |
| ACC-ROLE-007 | 本人改密后清除强制改密标记，撤销其他会话和全部 API Key，并轮换当前会话；管理员重置密码必须提交新密码、撤销全部会话和 Key、设置强制改密且响应不回显密码 | 分别执行本人改密和管理员重置，核对标记、会话、Key、响应及审计 |

### 13.2 数据模型与业务字段

| 编号         | 验收标准                                                                                                                                                                                      | 验证方法                                                                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| ACC-DATA-001 | 可建立多个仓库；每张单必须且只能有一个启用仓库                                                                                                                                                | 建两个仓库并分别入出库，尝试空仓库和停用仓库                                                                                              |

| ACC-DATA-006 | 所有出入库单必须有一个启用管理部门，全部明细继承                                                                                                                                              | 提交空部门和停用部门均失败                                                                                                                |
| ACC-DATA-007 | 项目仅存在于明细行且每行可选；同一单据可混用多个项目或部分留空；单据头出现 `project_id` 返回 422，每单不再限制一个项目                                                                                                                    | 创建混合项目、全空项目单据，并在单据头提交 `project_id` 核对 422                                                                                  |
| ACC-DATA-008 | 停用项目不能出现在任何新增明细行，也不能被已有草稿任一行提交使用；保存与提交均返回 409 `PROJECT_INACTIVE` 并列出行号；历史有效单据不变；启用后可再选                                                                                                              | 停用前后保存与提交混合项目单据、启用并核对历史快照                                                                                                          |
| ACC-DATA-009 | 同一物资可在同一单据中按不同项目拆成多行；同一 `(material_id, project_id)` 组合（空项目视为同一取值）不得重复，空项目行由 `(document_id, material_id)` 部分唯一索引兜底；库存按物资汇总校验和扣减 | 构造同物资跨项目拆行入库/出库，核对唯一索引、重复行拒绝与汇总余额 |
| ACC-DATA-010 | 明细保存项目显示名称快照，草稿保存时刷新、提交生效后冻结；详情、MCP 与导出按快照回放，不随基础资料变化 | 草稿阶段更换项目后核对快照刷新，提交后核对详情、导出与 MCP 快照 |
| ACC-DATA-011 | 入库每一明细厂家必填且启用；出库无厂家，传厂家字段返回 422                                                                                                                                    | 缺厂家入库、停用厂家、带厂家出库                                                                                                          |
| ACC-DATA-012 | 同一单据内同一物资同一项目不允许重复，不同项目可拆行；至少一行明细                                                                                                                                                          | 提交空明细、同物资同项目重复及同物资跨项目拆行草稿                                                                                                                  |
| ACC-DATA-013 | 已关联出入库数据的资料不能物理删除，只可停用；非零库存仓库不能停用；分类和物资停用后只影响入库，出库由库存决定；历史显示不受停用影响                                                          | 尝试删除/停用，验证停用物资可继续出库并查询历史                                                                                           |
| ACC-DATA-014 | 一级分类名称全局唯一；二级分类名称仅在所属一级分类内唯一，不同一级分类可同名；服务层与数据库均拒绝同级重名并返回 409                                                                          | 顺序及并发创建同名分类，检查首尾空白、停用记录和数据库唯一索引                                                                            |
| ACC-DATA-015 | 物资名称仅在直接所属分类内唯一，同分类不可重名，不同分类可同名；物资编码仍全局唯一                                                                                                            | 创建同分类同名及跨分类同名物资，顺序和并发请求均核对结果与唯一索引                                                                        |
| ACC-DATA-016 | 一级或二级分类有子分类、直接或间接物资时均禁止删除；只有无子分类、无物资且完全未引用的分类可删除；物资停用不改变挂载判定                                                                      | 分别删除空分类、有子级分类、直接/后代挂物资分类、含停用物资分类及历史引用空分类，核对 409 与数据保留                                      |
| ACC-DATA-017 | 数据库不存在 XLSX 解析批次、解析错误行或上传文件表；单据不保存解析来源和跳过行信息                                                                                                            | 检查迁移、schema 和单据字段                                                                                                               |
| ACC-DATA-018 | 分类存在任一未停用子分类或未停用物资时禁止停用；一级分类的判定覆盖全部二级子分类及这些子分类下的物资，以及直接挂在一级分类下的物资；判定口径与删除口径一致                                    | 分别构造有未停用子分类、有未停用物资、下级全部停用三种分类，调用停用接口核对 409/成功及列表状态                                           |
| ACC-DATA-019 | 分类停用被拒返回 409，`CATEGORY_HAS_ACTIVE_CHILDREN`/`CATEGORY_HAS_ACTIVE_MATERIALS` 按阻碍类型区分，`details` 列出未停用子分类名称与数量、未停用物资编码与名称；停用被拒时分类状态不变 | 停用有下级资料的分类并检查错误码、details 内容和数据库状态                                                                                |
| ACC-DATA-020 | 分类停用不级联：停用一级分类不会自动停用其子分类或物资；必须自底向上逐层停用后才可停用上级                                                                                                    | 直接停用含启用子分类的一级分类被拒后，逐层停用并再次尝试                                                                                  |
| ACC-DATA-021 | 仓库、部门、项目、厂家名称在各自表内唯一；重复名称返回 409 `NAME_CONFLICT`，`details.resource` 正确标识资源类型                                                                           | 逐类创建同名记录、仅首尾空白差异记录，并并发创建核对结果与唯一索引                                                                        |
| ACC-DATA-022 | 六类名称（仓库、部门、项目、厂家、分类、物资）仅去除首尾空白后精确比较，不折叠大小写、不删除内部空白；停用记录仍占用名称                                                                      | 创建仅大小写不同、内部空白不同、停用后重名的记录，逐项核对允许/拒绝结果                                                                   |
| ACC-DATA-023 | 分类停用检查与停用写入在同一写事务内完成，并发启用子分类或新增物资不会产生“父分类已停用、子分类仍启用”的状态                                                                                | 并发停用一级分类与启用子分类/新增物资，多轮核对最终状态不变量                                                                             |
| ACC-DATA-024 | 仓库、部门、项目、分类、物资、厂家停用后均可由公司管理员启用；启用只改 `is_active` 并写审计，不改历史单据、明细快照或库存汇总                                                               | 逐类停用后启用，对比启用前后单据、快照和库存视图                                                                                          |
| ACC-DATA-025 | 启用二级分类要求一级父分类已启用；启用物资要求所属分类及一级父分类均已启用；违反返回 409 `PARENT_INACTIVE` 并指明未启用上级                                                                 | 停用父分类后尝试启用子分类和物资，再逐级启用后重试                                                                                        |
| ACC-DATA-026 | 启用已启用记录幂等成功、返回当前对象且不重复写审计；停用与启用均写审计日志并保留前后状态                                                                                                      | 重放启用请求并查询审计条数与内容                                                                                                          |
| ACC-DATA-027 | 启用后资料立即可用于新单据（分类、物资用于入库）；操作员调用任一类启用接口返回 403                                                                                                            | 启用后建单验证可用性，并用操作员会话逐类调用启用接口                                                                                      |
| ACC-DATA-028 | 六类实体字段均为 `code`，按对应拼音首字母前缀和固定 5 位补零序号自动生成、各自唯一且不可修改；页面/API/MCP 创建均不接收编码，停用或删除后不复用；并发生成无重复，失败时记录与计数器整体回滚 | 检查 schema 和页面，逐类尝试传入 `code`/旧字段并核对拒绝结果；验证 `CK-00001` 等固定 5 位格式、并发创建、故障注入及停用删除后检查编码 |
| ACC-DATA-029 | 任一仓库物资余额不得超过 `MAX_BALANCE_MILLI`；多行合法最大数量汇总不触发 SQLite 溢出，超限提交返回 409 `BALANCE_LIMIT_EXCEEDED` 且不改变库存 | 构造边界及超限多行入库，直接查询 `quantity_milli`、视图和事务结果 |
| ACC-DATA-030 | 创建单据保存规范化 `request_fingerprint`；省略值与默认值、数量 `1` 与 `1.0`、逐行备注省略/`null`/空字符串归一后同指纹，明细顺序不同视为不同请求；Web/API 同键不同指纹返回 `REQUEST_ID_CONFLICT`；MCP 建单写入 `created_source='MCP'` 且该值不进入工具输入 | 顺序/并发重放普通 API 与 MCP 创建，检查指纹、`created_source`、单据数量和审计 |
| ACC-DATA-031 | 备注仅存在于明细行且逐行独立；`stock_documents` 不含 `remark`，`stock_document_lines.remark` 可空、去首尾空白后最多 500 字符；单据头出现 `remark` 返回 422；备注不同不影响同一物资同一项目的重复判定 | 创建/修改逐行备注单据，检查 schema、响应和唯一索引；单据头传 `remark` 核对 422 |

### 13.3 入库、出库、库存与软删除

| 编号         | 验收标准                                                                             | 验证方法                                             |
| ------------ | ------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| ACC-FLOW-001 | 入库草稿不影响库存；提交后按数量增加；操作者和生效时间完整                           | 提交前后查询视图及单据                               |
| ACC-FLOW-002 | 出库草稿不影响库存；可用量等于出库量可提交，超过则整单失败                           | 边界值 10 出库 10，再尝试出库 0.001                  |
| ACC-FLOW-003 | 多明细出库任一物资不足时，其他物资也不扣减，单据不生效                               | 构造一项足、一项不足并检查全部明细                   |
| ACC-FLOW-004 | 已生效单据和明细不能更新或物理删除；软删除只写入删除标记并保留记录                   | API 修改、软删除及直接 SQL 尝试                      |
| ACC-FLOW-005 | 操作员仅可软删除本人创建的已生效单，删除他人单据返回 403；管理员可软删除全部已生效单 | 分别使用两种角色软删除本人及他人单据                 |
| ACC-FLOW-006 | 已软删除单据及明细完整保留，历史查询显示软删除状态                                   | 软删除后查询单据头、明细、快照和状态                 |
| ACC-FLOW-007 | 已生效单软删除后退出实时库存汇总；若移除入库单会使余额小于零或移除出库单会使余额超过上限，分别返回 409 `NEGATIVE_STOCK`/`BALANCE_LIMIT_EXCEEDED` 且不写删除标记；草稿不使用软删除 | 先入库再出库后软删除入库单，核算库存、软删除状态和审计；再构造余额上限边界软删除出库单 |
| ACC-FLOW-008 | 两个并发出库不能都基于旧余额成功；最终无负库存且只有合理成功结果；软删除与提交并发不能产生负余额 | 余额 10，并发两个出库 8，重复多轮；并发软删除入库与出库提交 |
| ACC-FLOW-009 | 锁超时、校验异常或模拟进程故障不产生半张有效单据                                     | 故障注入并核对头、行、计数器和库存                   |
| ACC-FLOW-010 | 库存不按项目、部门或厂家分账；项目、部门、厂家只用于归属筛选和统计，不改变余额定义                           | 同库同物资跨项目入库后合并出库                       |
| ACC-FLOW-011 | 混合项目单据：同一物资按项目拆行后提交按物资汇总校验与扣减；单据按项目筛选任一行匹配即命中；流水按行返回该项目数量；库存余额仍不按项目分账 | 构造混合项目出入库，分别按项目筛选单据和流水并核对汇总数与余额 |
| ACC-FLOW-012 | 重复创建请求和重复提交不会生成重复有效业务记录：Web/API 重放同一 `request_id` 返回原单，MCP 在 300 秒窗口内重放相同内容返回原单并标 `deduplicated=true` | 重放 `request_id`、重放 MCP 相同内容及提交请求 |
| ACC-FLOW-013 | 单据按厂家筛选时只匹配入库明细，任一入库行匹配即返回整单；出库行不产生厂家匹配；MCP `document_list` 与 `GET /documents` 口径一致 | 构造同一仓库入库/出库单，分别按厂家 ID 和编码筛选并核对结果 |

| ACC-API-009 | 所有错误的 `details` 均为包含 `resource` 和 `items` 的对象；Web/API 创建单据的 `request_id` 为客户端幂等键，其他请求及全部 MCP 请求为服务端请求标识 | 对各类错误做 schema 校验，重试创建并核对标识 |
