## 4. 角色与权限模型

### 4.1 固定角色

| 角色代码          | 名称       | 数据范围     | 核心职责                                                                                                                                                 |
| ----------------- | ---------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `COMPANY_ADMIN` | 公司管理员 | 全部系统数据 | 管理用户、仓库、部门、项目、分类、物资和厂家；修改、删除和提交全部出入库单；查询审计；手动备份                                                           |
| `OPERATOR`      | 库存操作员 | 全部业务数据 | 查询基础资料、库存和单据；创建出入库单；仅可修改、删除本人创建的出入库单，可提交全部普通出入库草稿；使用 XLSX 快速录入和单据导出；不可管理基础资料或用户 |

约束：

- 一个账户只能拥有一个固定角色。
- 系统不设置系统管理员，也不提供公司创建、切换、启用或禁用功能。
- 本人单据按 `created_by` 认定。操作员不得修改、删除他人创建的出入库单，但可提交他人创建的普通草稿；已生效单据不可修改，只能软删除。
- 至少保留一个启用的公司管理员。停用或降级最后一名公司管理员必须被拒绝；禁用、降级和角色变更必须在 `BEGIN IMMEDIATE` 写事务内取得写锁后重新统计启用管理员，数量不足两人时整笔回滚，防止并发操作同时通过检查。

### 4.2 权限矩阵

`管理`包含新建及按规则删除或停用，不包含修改；`全部普通草稿`包含查看和提交，修改和删除按单据创建者限权。

| 能力                                         | 公司管理员 | 库存操作员 |
| -------------------------------------------- | ---------: | ---------: |
| 管理公司管理员和库存操作员                   |         是 |         否 |
| 重置用户密码                                 |         是 |         否 |
| 管理仓库、部门、项目、分类、物资、厂家       |         是 |         否 |
| 停用、启用仓库、部门、项目、分类、物资、厂家 |         是 |         否 |
| 查询基础资料、库存和单据                     |         是 |         是 |
| 创建普通出入库草稿                           |         是 |         是 |
| 修改、删除普通出入库草稿                     |       全部 | 仅本人创建 |
| 提交全部普通出入库草稿                       |         是 |         是 |
| 下载出入库 XLSX 模板                         |         是 |         是 |
| 解析 XLSX 并填入新建单页面                   |         是 |         是 |
| 导出单张单据详情                             |         是 |         是 |
| 软删除已生效出入库单                         |       全部 | 仅本人创建 |
| 查看审计日志                                 |         是 |         否 |
| 手动执行及查询备份                           |         是 |         否 |
| 创建、查看元数据和吊销本人 API Key           |         是 |         是 |
| MCP 查询仓库、部门、厂家、分类、物资和单据   |         是 |         是 |
| MCP 新增仓库、部门、厂家、分类和物资         |         是 |         否 |
| MCP 新增出入库草稿或直接提交新单             |         是 |         是 |

### 4.3 用户生命周期

1. 空数据库首次启动时，根据初始化环境变量创建首位公司管理员。
2. 公司管理员可创建库存操作员，也可创建额外公司管理员。
3. 公司管理员在创建请求中设置初始密码；新建账户获得该一次性初始密码并强制首次改密。
4. 管理员重置用户密码时，必须在请求中提交符合密码规则的新密码；服务端不在响应中回显密码，撤销目标用户全部会话和 API Key，并设置强制改密标记。用户本人修改密码成功后清除强制改密标记，撤销其他会话和全部 API Key，并轮换当前会话使其继续有效；改密后需要重新创建 Key。初始密码仍按第 3 条强制首次改密。
5. 禁用用户时立即撤销会话和全部 API Key，不删除用户资料和历史单据署名；角色变化同样撤销全部会话和 Key。
6. 页面隐藏按钮和 `tools/list` 过滤都不是权限控制；每个 API 和每次 MCP 工具调用必须在服务端重新校验角色、Key 和账户状态。
