## 11. 安全、可靠性与性能要求

### 11.1 安全要求

- 所有输入在服务端验证长度、枚举、UUID、数量和状态；ORM 参数化查询，禁止字符串拼接 SQL。
- Jinja2 默认转义；富文本不在本期范围内。
- Web 页面和 `/api/v1` 创建单据使用客户端 `request_id` 并在错误和日志中沿用该值；其他 `/api/v1` 请求和全部 MCP 请求由服务端生成请求 ID，二者不得在同一请求内混用。MCP 工具不接收 `request_id`，其建单去重按[《MCP 服务与工具》7.9 第 6 条](08-MCP服务与工具.md#79-mcp-原子创建并提交)的内容指纹与时间窗口判定。错误日志不得泄露密码、会话、完整 API Key、Authorization 头和数据库内容。
- 登录限流、MCP 按 Key/IP 限流、CSRF、会话过期、API Key 哈希与生命周期、Origin/Host 校验、密码哈希、最后公司管理员保护必须自动化测试。
- 操作员调用用户管理、基础资料写入、基础资料停用或启用、审计和备份接口必须返回 403；修改或删除他人出入库单也必须返回 403。
- 公司、租户和数据库路径参数不具有切换数据上下文的作用；收到未知参数时按接口契约拒绝或忽略，不得据此拼接路径。
- XLSX 上传按不可信文件处理：限制 5 MiB 和 2,000 非空数据行，校验 ZIP/工作簿结构及解压后尺寸，拒绝异常嵌套和外部关系；不执行宏、公式或外部链接，不在服务器调用 Office。
- 导出中的所有用户可控文本必须以字符串单元格写入，禁止将以 `=`, `+`, `-`, `@` 开头的文本解释为公式；文件名、响应头和错误消息须防止注入。
- 上传临时文件使用服务端随机路径和最小权限，解析结束立即删除；日志不记录完整工作表、原始文件内容或敏感服务器路径。
- 解析响应和浏览器填单数据均按不可信输入处理，保存和提交重新鉴权并校验；不得因数据来自 XLSX 解析而放宽普通单据规则。
- 内网 HTTP 是已接受风险，不得将其描述为加密传输或公网安全方案；该风险同样适用于 MCP Bearer Key。
- MCP 工具输入按不可信输入处理，schema 校验不能替代业务校验；工具描述和返回数据不得诱导绕过权限、资料状态、精度或库存规则。`tools/list` 的过滤和 `tools/call` 的服务端鉴权缺一不可。

### 11.2 可靠性要求

- 任何提交、初始化和用户创建都可安全重试，不产生重复有效业务记录。
- XLSX 解析不要求幂等键且无副作用；重复上传不得创建、修改或删除任何业务数据。草稿创建按 `request_id` 幂等，网络重试和页面重复提交不得生成重复草稿。
- 数据库异常、进程终止或锁超时不得产生半张有效单据。新建页直接提交时若创建后提交失败或结果不确定，客户端使用原 `request_id` 重试创建并先查询已有草稿，再决定后续操作。
- MCP 创建与直接提交必须按[《MCP 服务与工具》7.9](08-MCP服务与工具.md#79-mcp-原子创建并提交)保证事务原子性和 300 秒窗口内容去重；直接提交失败不留下草稿，窗口内重放相同内容返回原单及 `doc_no` 并置 `deduplicated=true`，不重复建单、不重复写审计。API Key 创建、吊销和用户状态变化不得产生半撤销状态。
- 备份任务异常必须告警并在备份页面显示；不能仅以“任务已执行”代替“备份成功”。
- 应用启动时检查数据目录、权限、PRAGMA、迁移状态和调度器状态。
- 日志使用本地时区展示、UTC 存储，单条包含时间、级别、请求 ID、模块和错误摘要。

### 11.3 容量与性能基线

- 全系统 20 个在线用户。
- 至少支持 100,000 条有效单据明细。
- 参考环境：2 vCPU、2 GB 可用内存、SSD、应用与数据库同机。
- 预热后，10 个并发查询用户持续测试 5 分钟，常用分页列表和库存查询服务端响应时间 P95 不超过 2 秒，错误率低于 0.1%。
- 提交优先保证正确性，不承诺高写入吞吐；锁冲突必须明确反馈。
- 在参考环境且无其他写入时，2,000 行 XLSX 无副作用解析或单据导出的单次服务端处理目标不超过 10 秒，且不得发生内存溢出；超过目标时优先优化流式读写和批量名称解析，不放宽校验。
- 名称解析必须批量查询并建立候选映射，禁止对每一行、每一个字段分别发起可避免的重复数据库查询。
- 使用 SQLite `EXPLAIN QUERY PLAN` 检查库存、单据列表和流水查询，不允许对 10 万明细反复执行无索引的全表扫描。
- 超过基线后应重新评估物化余额、归档或迁移到客户端/服务器数据库；不得悄然改变库存正确性规则。
- MCP 查询使用与普通列表相同的分页、索引和批量查询，工具清单的 schema 可按进程缓存，但权限过滤不得缓存旧角色。限制单请求明细行数和响应大小，长单据按 `doc_no` 查看完整明细时须流式构造结构化结果并避免多份大对象驻留内存；关联编码使用批量 join，禁止按明细逐行查询。
