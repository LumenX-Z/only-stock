## 7. 库存计算与核心业务流程

> 7.8 见[《XLSX 模板、快速录入与导出》](07-XLSX模板、快速录入与导出.md)，7.9 见[《MCP 服务与工具》](08-MCP服务与工具.md)。

### 7.1 库存视图

库存只按“仓库 + 物资”汇总，不按项目、部门或厂家分账。草稿和已软删除单据不计入库存，其余已生效单据计入。

符号规则：

| 单据 | 符号 |
| ---- | ---- |
| 入库 | +1   |
| 出库 | -1   |

库存余额（千分比整数）：

```text
balance_milli = SUM(line.quantity_milli * direction_sign)
```

概念视图：

```sql
CREATE VIEW v_inventory_balance AS
SELECT
    d.warehouse_id,
    l.material_id,
    SUM(
        l.quantity_milli * CASE
            WHEN d.doc_type = 'INBOUND' THEN 1
            WHEN d.doc_type = 'OUTBOUND' THEN -1
        END
    ) AS balance_milli
FROM stock_documents d
JOIN stock_document_lines l ON l.document_id = d.id
WHERE d.status = 'POSTED' AND d.deleted_at IS NULL
GROUP BY d.warehouse_id, l.material_id;
```

实现要求：

- 零余额记录可能不出现在视图中，查询时用零补齐，禁止把缺行误判为错误。
- 对 `stock_documents(status, warehouse_id)`、`stock_document_lines(document_id)`、`stock_document_lines(material_id)`、`stock_document_lines(project_id)` 建立索引，并通过测试数据验证查询计划。
- 项目过滤通过明细行关联完成，单据任一行匹配即命中；部门过滤通过单据头、厂家过滤通过入库明细完成；厂家筛选只用于单据查询，库存流水不提供厂家筛选；均不改变库存余额定义。
- 余额上限按[《数据模型与实体约束》6.6](05-数据模型与实体约束.md#66-数量精确存储)执行；库存视图及任何提交前计算的余额必须落在 `[0, MAX_BALANCE_MILLI]` 内，不能只依赖输出层截断或浮点比较。

### 7.2 通用草稿规则

1. 公司管理员和库存操作员均可创建入库或出库草稿。
2. 公司管理员可编辑、删除、提交全部普通出入库草稿；操作员仅可编辑、删除本人创建的普通出入库草稿，但可提交全部普通出入库草稿。
3. 草稿保存时校验字段结构、资料归属和基本状态，但不影响库存。
4. 草稿可修改仓库、部门、厂家、数量和明细（含逐行项目和备注）；提交后全部冻结。
5. 提交时必须再次校验所有业务规则，不能信任保存草稿或 XLSX 解析时的结果。
6. 提交采用“状态 + 版本”幂等保护；已成功提交的重复请求返回 409，客户端应先查询原单，不得再次生成新单。
7. Web 页面和 `/api/v1` 的创建请求使用客户端 `request_id` 去重，防止网络重试产生重复草稿；MCP 建单不接收客户端幂等键，改由服务端按[《MCP 服务与工具》7.9 第 6 条](08-MCP服务与工具.md#79-mcp-原子创建并提交)在时间窗口内去重。
8. 新建页的“提交生效”先调用 `POST /documents` 创建草稿，再调用 `POST /documents/{id}/submit`。若创建成功而提交失败或结果不确定，页面必须明确提示草稿可能已经存在，展示已取得的草稿 ID/链接，并在重试创建时复用原 `request_id`；不得盲目重复建单。
9. MCP `document_create(submit=false)` 只创建草稿，规则与普通创建接口一致；`submit=true` 则按[《MCP 服务与工具》7.9](08-MCP服务与工具.md#79-mcp-原子创建并提交)在一个写事务内创建并提交，不执行网页的两阶段失败保留草稿行为。MCP 工具不接受 `request_id` 参数，两种模式均由服务端生成该标识并按[《MCP 服务与工具》7.9 第 6 条](08-MCP服务与工具.md#79-mcp-原子创建并提交)去重。

### 7.3 入库流程

**参与角色**：库存操作员或公司管理员。

1. 选择启用的仓库、管理部门；每条明细可单独选择启用项目、填写备注或留空；也可通过 XLSX 将这些内容填入新建页。
2. 添加入库明细：物资、数量、必填厂家、可选项目、可选备注。
3. 系统校验每单一个仓库、每单一个部门、同一物资同一项目不重复、数量大于零、逐行备注不超过 500 字符。
4. 项目由录单人员在每条明细上决定是否填写；非空时必须为启用项目；同一单据不同明细可使用不同项目，也可部分留空。
5. 保存为 `DRAFT`，库存不变。
6. 提交时开启 `BEGIN IMMEDIATE` 写事务并重新读取草稿版本。
7. 逐行重新校验仓库、部门、物资、厂家和项目状态、备注长度，以及数量类型和精度。
8. 在事务内按仓库与物资汇总本单增加量，校验提交后余额不超过 `MAX_BALANCE_MILLI`；超限返回 409 `BALANCE_LIMIT_EXCEEDED` 并整单回滚。校验通过后写入或更新有效单据状态、生效时间和操作者，库存视图立即可查询到增加量。
9. 提交事务失败则整单回滚；成功后原单不可修改，只可按权限软删除。

**关键校验点**：入库厂家逐行必填；项目启用状态在保存和提交时逐行重检，停用项目返回 409 `PROJECT_INACTIVE` 并列出行号；整数物资不得出现小数；同一物资在同一项目下不得拆成重复行，不同项目可拆行；备注按行独立，最多 500 字符，不参与重复判断。

### 7.4 出库流程

**参与角色**：库存操作员或公司管理员。

1. 选择启用的仓库、管理部门；每条明细可单独选择启用项目、填写备注或留空。
2. 添加出库明细：物资、数量、可选项目、可选备注；页面和 API 均不提供厂家字段。
3. 保存草稿，库存不变。
4. 提交时开启 `BEGIN IMMEDIATE`，取得数据库写锁。
5. 在事务内从 `v_inventory_balance` 重新计算本仓库涉及物资的当前余额。
6. 按物资汇总全部明细计算提交后的预计余额（同一物资按项目拆行时合并计算）；任一物资小于零则整单拒绝，任一余额超过 `MAX_BALANCE_MILLI` 亦整单拒绝并返回 409 `BALANCE_LIMIT_EXCEEDED`。
7. 逐行校验项目、部门、仓库状态、备注长度和全部数量规则；停用项目同样拒绝并返回 409 `PROJECT_INACTIVE`；分类和物资停用不影响出库，出库涉及的分类和物资由库存决定。
8. 所有校验通过后将整单置为 `POSTED`，库存视图立即扣减。
9. 库存不足返回 `INSUFFICIENT_STOCK`，包含物资编码、可用量和请求量，不写入任何部分明细或状态变更。

**边界规则**：可用量等于出库量时允许提交；结果为整数零或千分比整数零。草稿阶段显示的可用量仅供参考，不是提交承诺。

### 7.5 已生效单据软删除流程

**参与角色**：公司管理员可软删除全部已生效出入库单；库存操作员仅可软删除本人创建的已生效出入库单。

1. 选择一张已生效且未软删除的出入库单；已生效单据不可修改。
2. 服务端按 `created_by` 校验操作员的单据归属，管理员不受单据创建者限制。
3. 开启 `BEGIN IMMEDIATE` 写事务，重新读取单据状态；已软删除的单据返回 409 `DOCUMENT_ALREADY_DELETED`，不得重复写入删除标记或审计。
4. 在事务内按该单据的仓库和全部明细物资重新计算余额，将本单从“有效单据”集合中移除后得到的预计余额必须满足 `0 <= balance_milli <= MAX_BALANCE_MILLI`；任一物资不满足则整单拒绝并返回 409：小于零返回 `NEGATIVE_STOCK`，超过上限返回 `BALANCE_LIMIT_EXCEEDED`，不得写入删除标记。
5. 校验通过后写入 `deleted_at` 和 `deleted_by`，保留单据头、全部明细及历史快照，不物理删除记录。
6. 软删除后的单据不再计入库存汇总，历史查询仍保留其记录和软删除状态。库存重算、删除标记和审计必须在同一事务内提交。

### 7.6 项目停用与启用

- 公司管理员可停用项目，也可启用已停用项目。
- 停用项目不得出现在任何新增明细行中，也不得被已有草稿的任一行在提交时使用；保存和提交均返回 409 `PROJECT_INACTIVE`，`details` 列出行号与项目编码/名称。
- 项目停用不改变任何历史有效单据明细上的项目字段与名称快照。
- 启用后可再次用于新出入库单。
- 停用和启用都写审计日志；列表默认只显示启用项目。

### 7.6.1 基础资料停用与启用通则

本节规则适用于仓库、部门、厂家、分类和物资；项目按 7.6 处理，并同样适用下列通用约束。

- 停用与启用均仅由公司管理员执行，操作员调用一律返回 403。
- 停用不修改任何历史单据、明细快照或库存汇总；启用同样不修改，也不触发库存重算。
- 停用与启用都在同一写事务内完成并写审计日志，记录操作者、对象、动作和前后状态。
- 停用后该资料不再可用于新建或提交单据（分类、物资为不再可用于入库）；出库仍按库存与出库流程判定，不因资料停用而拒绝。
- 启用已启用的记录幂等成功并返回当前对象，不重复写审计。
- 启用下级资料要求上级已启用：启用二级分类要求其一级父分类已启用，启用物资要求其直接所属分类及该分类的一级父分类均已启用；违反时返回 409 `PARENT_INACTIVE`。
- 列表默认仅显示启用记录，可切换查看已停用记录；已停用记录始终可被查询与历史引用。

### 7.7 并发与原子性

场景：同一仓库某物资余额为 10，两张出库单分别申请 8。

1. 第一张取得 `BEGIN IMMEDIATE` 写锁，事务内读取 10，扣减 8 后提交，余额为 2。
2. 第二张等待写锁，取得锁后必须重新读取余额 2，不能以等待前的 10 为依据。
3. 第二张因 2 小于 8 整单失败，最终余额为 2，无负库存。

任何多明细单据只要一项校验失败，单据头、全部明细、计数器和审计业务写入必须在同一事务内回滚。审计失败日志可在事务外单独记录，但不能伪装为业务成功。XLSX 部分填入不是数据库部分提交：错误行从未成为表单有效明细，有效行只有在用户操作后才组成完整草稿；该草稿后续提交仍必须整单成功或整单失败。
