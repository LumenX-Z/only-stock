## 3. 技术架构

### 3.1 逻辑架构

```text
浏览器（Jinja2 页面 / HTMX / JSON API）       MCP 客户端
                  |                              |
             HTTP 会话                    API Key Bearer
                  |                              |
                  └──────────┬───────────────────┘
                             |
                  FastAPI 单一应用进程
                  ┌─────────┴─────────┐
                  |                   |
             认证与授权            业务服务与事务
             会话 / API Key        页面 / API / MCP 共用
                  └─────────┬─────────┘
                            |
                    单一 SQLite 数据库
                    /data/inventory.sqlite3
```

XLSX 快速录入由浏览器调用无副作用解析接口，取得表单数据和行级错误摘要。解析接口只读取基础资料，不取得数据库写锁，不写入单据、解析批次或审计记录。用户手工保存或提交后，才进入普通单据业务服务与事务。

MCP 由官方 SDK 的 Streamable HTTP 服务挂载到同一 FastAPI 应用，端点为 `http://服务器IP:8000/mcp`。MCP 适配层只负责协议、API Key 认证、工具过滤、参数转换和结果映射；入站把 `code`/`doc_no` 解析为内部 UUID，出站把内部关联映射回业务编码，内部 UUID 不得进入任何工具参数、结果或错误 `details`；不得复制基础资料、单据、权限、库存或数量规则。所有工具均通过普通业务服务访问同一 SQLite 数据库，每次请求使用独立数据库会话。

### 3.4 SQLite 连接要求

每个新连接必须执行：

```sql
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA busy_timeout = 5000;
```

要求：

1. `foreign_keys` 必须逐连接启用，并通过启动自检确认。
2. WAL 文件必须与数据库一同持久化，但恢复以在线备份生成的完整数据库文件为准。
3. 禁止通过 SQL `ATTACH` 引入其他数据库作为业务数据来源。
4. 所有写操作使用短事务，禁止在事务内调用外部服务或等待用户输入。
5. 单据提交必须显式使用 `BEGIN IMMEDIATE`，不得依赖 ORM 隐式提交。
6. 捕获 `SQLITE_BUSY`/`SQLITE_LOCKED`，回滚后返回明确冲突，不得出现部分成功。

### 3.5 代码风格与 Ruff 校验

Ruff 是唯一的代码风格检查与格式化工具，规则集中配置在 `pyproject.toml`，不得在编辑器、IDE、CI 脚本或其他配置中维护第二套规则。Ruff 通过 uv 作为开发依赖安装并锁定版本，不进入运行时镜像。

#### 3.5.1 配置基线

`pyproject.toml` 至少包含以下配置，且不得弱化：

```toml
[tool.ruff]
target-version = "py313"
line-length = 100
src = ["app", "tests"]
extend-exclude = ["alembic/versions"]

[tool.ruff.lint]
select = ["E", "F", "W", "I", "UP", "B"]
ignore = ["E501"]

[tool.ruff.lint.isort]
known-first-party = ["app", "tests"]

[tool.ruff.format]
quote-style = "double"
indent-style = "space"
```

`src` 声明项目源码目录；`known-first-party` 明确把本项目的 `app`、`tests` 视为第一方包，避免 isort 将 `app` 误判为第三方而打乱导入分组。

| 规则组 | 作用 | 要求 |
|---|---|---|
| `E`、`W` | pycodestyle 错误与警告 | 空白、缩进和语句结构符合 PEP 8；行长由 `ruff format` 与 100 列约定控制，`E501` 不单独报错 |
| `F` | Pyflakes | 禁止未使用导入或变量、未定义名称和重复定义 |
| `I` | isort | 导入按标准库、第三方、第一方分组排序；`src` 声明源码目录，`known-first-party` 声明本项目包 |
| `UP` | pyupgrade | 直接使用 Python 3.13 语法，不保留旧版本兼容写法 |
| `B` | flake8-bugbear | 拦截可变默认参数、循环闭包等常见缺陷 |

`alembic/versions/` 由 `alembic revision --autogenerate` 生成，整体不纳入自动校验；确需手写迁移时按本节风格编写并在评审中检查。其他手写脚本必须符合本节要求。`app/` 与 `tests/` 使用同一套规则，测试代码不放宽。

FastAPI 的依赖注入和参数声明统一使用 `Annotated[T, Depends(...)]`、`Annotated[T, Query(...)]` 形式，不使用函数调用作为参数默认值，避免触发 `B008`。

#### 3.5.2 执行命令

```bash
# 只读校验；两条命令均须退出码 0
uv run ruff check .
uv run ruff format --check .

# 本地修复；执行后人工复核差异
uv run ruff check --fix .
uv run ruff format .
```

1. `ruff check` 的任何告警都视为失败，不以“仅警告”放行。
2. 自动修复只处理安全规则；其余问题必须手工修改，不得通过删除规则、扩大 `ignore` 或排除目录来通过校验。
3. 禁止无边界的 `# noqa`；确需忽略时写成 `# noqa: <规则代码>`，并在该行或上一行说明原因。
4. 调整规则集、`ignore`、`per-file-ignores` 或排除路径时，先修改本节和 `pyproject.toml`，再改代码；不得在代码中临时禁用规则。

#### 3.5.3 校验范围与门禁

- 校验仓库内全部 `.py` 文件（`app/`、`tests/`、`alembic/` 中的 `env.py` 等手写脚本、根目录脚本），不包含虚拟环境、构建产物和工具缓存。
- 提交前、阶段门禁和发布检查均执行 3.5.2 的两条只读命令；阶段门禁命令见 [TASKS.md](../TASKS.md) 的“阶段门禁命令清单（权威）”。
- 首次创建 `pyproject.toml` 时写入本节配置并锁定 Ruff 版本；新增代码不得降低规则强度。
