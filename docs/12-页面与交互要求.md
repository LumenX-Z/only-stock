## 9. 页面与交互要求

1. 登录、首次改密、用户管理、基础资料、库存查询、单据列表、单据编辑、软删除、审计、备份和“我的 API Key”页面。
2. 页面根据角色隐藏无权限入口，但后端仍为最终权限边界。
3. 草稿明确显示“不计入库存”；提交按钮二次确认，成功后显示生效时间和单号。
4. 出库页面可用量仅供参考，库存不足时定位到具体明细并显示服务端最新可用量。
5. 整数物资输入控件步长为 1；小数物资步长为 0.001，但服务端必须独立校验。
6. 物资分类选择允许一级或二级分类，不允许留空；二级分类应显示所属一级分类，避免同名节点歧义。创建分类和物资时提示对应唯一范围及重名冲突；创建仓库、部门、项目、厂家时在表单内提示名称须全表唯一，重名冲突就地回显冲突记录名称与启用状态，不得保存后才以通用错误提示。分类删除被拒时明确显示存在子分类、挂有物资或其他引用，不得提供绕过规则的强制删除。六类基础资料的新建表单均不得出现 `code` 输入框、隐藏字段、默认占位值或客户端预生成逻辑，前端必填、格式和唯一性校验中同步删除编码校验，提交请求体不得携带 `code`。创建成功后，列表、详情及创建结果页只读展示服务端返回的 `code`；编码生成失败时保留用户已填写的其他字段并展示明确错误，不得要求用户手工补码。
7. 每条明细行的项目选择默认仅列启用项目，允许留空；提供把某行项目应用到全部明细的便利操作，但它只影响当前表单，项目仍按行保存；入库厂家必填，出库页面无厂家输入。
8. 停用项目、停用资料、有效历史单据和已软删除单据仍可在历史查询中显示，并带有状态标识。
9. 写冲突、版本冲突和库存不足不得只显示通用“服务器错误”。
10. 所有列表分页；大数据量不得在浏览器一次加载全部记录。XLSX 快速录入所得当前单据明细是编辑表单的必要例外，最多 2,000 行，应采用分页、增量渲染或等价方式避免页面失去响应。
11. 入库、出库新建页分别提供模板下载和文件选择入口，上传前显示“仅用于填入当前新单、不自动保存或提交、最大 5 MiB/2,000 非空数据行”。已有草稿编辑页不提供 XLSX 入口。
12. 非空表单须经确认才解析，成功后整体替换单据头和全部有效明细，失败保留原内容。解析期间禁用重复上传按钮；同一文件可重复解析，不显示导入幂等或批次结果。
13. 解析结果明确区分全部填入、部分填入和失败，展示总行数、成功填入/跳过行数及当前页错误摘要；部分填入必须在用户保存或提交前保持显著提示，不生成错误报告，不在草稿详情中延续。
14. 新建页保留“保存草稿”和“提交生效”两个人工按钮。直接提交依次调用创建和提交接口；创建成功但提交失败时显示已创建草稿及失败原因，重试创建复用原 `request_id`，不得重复建单。
15. 单据详情页提供单张 XLSX 导出入口；导出属于读取操作，不改变单据状态。下载模板和导出均须重新鉴权，不能使用公开永久链接。
16. 分类停用不得一键级联：页面在发起停用前展示未停用子分类数量、未停用物资编码与名称清单，说明需先自底向上停用下级资料，并提供跳转至下级资料的操作入口；不得提供级联停用、强制停用或绕过检查的选项。停用成功后该分类标记为不可用于入库。
17. 六类基础资料的停用均可通过启用接口恢复，停用确认框须写明“可随时重新启用，不影响历史单据与库存”；启用按钮仅在已停用记录上出现。启用因上级未启用被拒时，页面提示需先启用哪个上级分类并提供跳转入口。
18. “我的 API Key”对两种角色开放，只能管理本人 Key；列表显示用途名称、末四位、创建时间、最后使用时间和吊销状态。创建成功页完整 Key 仅显示一次，提供复制和明确的保管提示，离开或刷新后不可恢复；吊销须二次确认，已吊销 Key 不恢复。
19. 页面展示 MCP 地址 `http://服务器IP:8000/mcp` 及 Bearer 配置示例，示例使用占位符而非真实 Key；提示改密、角色变化和禁用会撤销 Key，最多 10 把有效 Key，以及内网 HTTP 明文传输风险。页面不得提供按角色选择权限或管理他人 Key 的入口。
